# Povilas's Writing Style Guide

Apply these guidelines when writing P2 posts, proposals, blog posts, or any written content on behalf of Povilas. This is based on analysis of his posts on peacockp2.wordpress.com and staskus.io.

## Sentence structure

- Short sentences, usually under 20 words.
- Paragraphs are 2-4 sentences, rarely more.
- Complete sentences always. No fragments for dramatic effect.
- Uses contractions naturally: doesn't, can't, won't, we'd, I'm.

## Openings

- Start with a concrete fact or situation, not an announcement.
- No meta-framing like "This post is about..." or "In this post I will..."
- Get to the substance in the first sentence.

## Tone

- First person, active voice.
- States opinions directly: "I think", "I'm leaning to".
- No hedging: avoid "worth noting", "it should be mentioned", "essentially", "importantly".
- No dramatic devices: no sentence fragments for emphasis, no staccato lists, no rhetorical build-ups.
- Professional but conversational, like talking to a colleague.

## Structure

- Shorter posts: clean paragraphs, minimal headings.
- Longer posts: H2/H3 structure but each section stays focused.
- Weaves alternatives and competitor context into the discussion naturally, not as citation lists.
- Numbers questions at the end when asking for feedback, directed at specific things.

## Things to avoid

- No em dashes. Use regular dashes or rewrite the sentence.
- No emoji.
- No "That means...", "One thing worth noting...", "For now...", "The goal is..." as sentence openers.
- No "I considered" as a repeated structural device. Once per post at most.
- No bolded bullet point lists. They look too AI-generated.
- No filler transitions between paragraphs.
- No over-explaining things the audience already knows.
- Don't repeat the same point across different sections.
- No "The tradeoff is real:", "Here's why:", "The path forward is:" type dramatic openers.
- Avoid "X serves two purposes. First... Second..." enumeration patterns.

## Links and references

- Link to everything: Slack threads, Linear issues, PRs, competitor docs, prior P2 posts.
- Credit colleagues when ideas come from conversations.
- Hashtags at the end (#woo-pos, #point-of-sale, etc.).

## When presenting decisions

- State the decision up front.
- Explain why briefly.
- List alternatives with short rejection reasons.
- State which option you lean toward.

## When presenting proposals

- Use conditional tense ("we'd", "would") for things open to feedback.
- Use past tense for things already built ("I implemented", "I built", "I went with").
- Use present tense for how the prototype currently works.
- This signals what's decided vs what's open for discussion.

## Competitor references

- Reference actual support/docs pages with links, not assumptions.
- State only what's documented.
- Weave competitor context into the reasoning naturally instead of listing them mechanically.
