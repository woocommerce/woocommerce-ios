Simplified model: No "Override" state in V1. Every permission is binary - allowed or hidden. This removes the manager override flow from V1 scope, which is a significant complexity reduction. We can add the three-state model (Allowed / Override / Hidden) in a future iteration when we have more gatable features like cash drawer and voiding.

Impact of removing Override from V1

What we keep

  • PIN entry & lock screen
  • Staff switching
  • Permission-gated UI (hide features)
  • Staff management in settings
  • Local + remote provider protocol

What we defer

  • Manager override modal/sheet
  • Three-state permission model
  • Approval tokens
  • Per-action override audit trail
A

Keep it simple - no overrides in V1

Binary permissions only. Cashier either can or can't. Less scope, ships faster. Add overrides when we have cash drawer / voiding.

B

Keep manager override for coupon creation

Cashier sees "Create Coupon (Manager Approval)" button. Manager enters PIN inline. Builds the override infrastructure now.
