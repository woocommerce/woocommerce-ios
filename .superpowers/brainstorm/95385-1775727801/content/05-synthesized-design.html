Synthesized Design - BA + PM Analysis

Both agents agree on the core model. A few nuances need your input.

1. Two Roles in V1 AGREED

Both BA and PM confirm: Owner == Manager for V1. Shopify's free tier ships with exactly 2 roles.

Manager

  • The logged-in WP user is always Manager
  • Full access to everything
  • Can approve override requests via PIN
  • Additional managers can be added as staff

Cashier

  • Staff added via POS Settings
  • Sales, payments, order history, apply coupons
  • Some actions need manager PIN approval
  • Cannot exit POS or access settings

2. POS Containment AGREED

Cashier is locked inside POS. The "Exit POS" button requires manager PIN.

Cashier taps "Exit POS" in floating menu
→ PIN modal: "Manager approval required to exit POS"
→ Manager enters PIN
→ App exits POS back to main WooCommerce tabs

No auto-lock for V1. No iOS gesture handling.
Guided Access recommended in settings, not integrated.
PM: "The meaningful containment boundary is 'Exit POS' (back to WooCommerce data), not 'leave the app entirely' (which shows the iPad home screen). This is the same model Square and Shopify use."

3. Login Gate for pos_cashier AGREED

pos_cashier WP role is added to the Role enum but NOT to eligible roles. Tailored error message.

Error Screen Title

"This account is set up for POS use only"

Error Screen Body

"POS cashier accounts can only be used at the point of sale. Ask your store manager to sign you in on the POS device, or log in with a different account."

Primary Button

"Log In With Another Account" (not "Retry")

4. Permission Model - Two Action Types YOUR INPUT

Both agents agree on the split. But you originally wanted everything overrideable. Here's their counter-argument:

Action Cashier Behavior Type
Process sale (card/cash) Allowed -
View order history Allowed -
Apply existing coupons Allowed -
Send receipts Allowed -
Process refund PIN Override Transactional
Create new coupon PIN Override Transactional
Exit POS PIN Override Containment
Access Settings Blocked Administrative
Manage Staff Blocked Administrative
Connect card reader Allowed Operational
BA: "No competitor uses manager override for administrative screens. If a manager needs settings, they do a full user switch via the lock screen."
PM: "If the manager enters their PIN and the cashier gets 'temporary access to Settings,' the cashier can change card reader config, store details, etc. 'Temporary' is hard to define. This creates subtle security gaps."

The question: Settings and Staff are blocked (cashier taps it, sees "Only the store manager can access this"). Manager uses the lock screen to switch to their own session when they need settings. Is this OK, or do you still want everything to be PIN-overrideable?

5. Guided Access AGREED

Document and recommend in POS Settings. Optionally detect if active. No programmatic integration.

BA: "No major POS competitor integrates with Guided Access or MDM programmatically. All document it as a recommended setup step."

PM suggests adding a "Device Security" section in POS Settings with a link to setup instructions and an optional green indicator if Guided Access is currently active.
