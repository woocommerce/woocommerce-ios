POS Containment & Override Authority

Two distinct levels of authority within POS

App Level
WooCommerce App
Orders, Products, Analytics...
← App Account Only →
POS Level
Point of Sale
Sales, Payments, Orders...

Level 1: App Account Holder Exit POS

Only the person who authenticated with WP credentials can cross this boundary. POS managers added as staff cannot - they've never logged into the app.

Cashier taps "Exit POS"
→ Modal: "Only the account owner can exit POS"
→ Account owner enters their PIN (or app password?)
→ App exits POS, returns to WooCommerce tabs

A POS Manager taps "Exit POS"
→ Same modal - even managers can't exit
→ Only the original WP-authenticated user can

Level 2: POS Manager Override Transactional

Any Manager (including added staff managers) can authorize restricted POS actions via PIN.

Cashier taps "Refund" on an order
→ Modal: "Manager approval required"
→ Any manager enters their PIN
→ Refund proceeds, cashier continues

Key insight: "Exit POS" is the ONLY action that requires app account authentication. Everything else within POS is either allowed or manager-overrideable. This creates a clean security boundary: POS is a contained world. The app behind it is a separate world.

Open question: Settings override UX

A

Manager switch (lock screen)

Cashier taps Settings, sees "Ask your manager." Manager goes to lock screen, enters their PIN, accesses settings as themselves. When done, locks device, cashier re-enters their PIN. Clean session boundary.

B

Inline PIN override (same as refunds)

Cashier taps Settings, manager enters PIN in modal, cashier gets temporary access until they leave settings. Simpler flow but the "temporary" boundary is fuzzy. Same concern PM raised about security.

C

Hybrid: PIN override switches active user

Cashier taps Settings, manager enters PIN in modal, device SWITCHES to manager session (not temporary access for cashier). Manager does what they need, then taps "Lock" to return to cashier flow. Override = session switch.
