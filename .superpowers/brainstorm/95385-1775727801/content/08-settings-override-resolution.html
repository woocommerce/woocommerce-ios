Settings Override: Docs vs. Your Preference

The investigation doc and your direction disagree. Let's resolve it.

Investigation Doc Says

"Hide, don't disable." Settings and Staff Management are marked No for Cashier (not Override). They should be invisible - not in the UI at all. Cesar's spike confirms: "settings and analytics hidden for cashiers via capability-based UI restrictions."

vs

You Said

"There are no unsupported flows, everything that is unsupported by the role could be done by manager override." This implies settings and staff management should also be overrideable.

Proposed Resolution: Quick User Switch

Settings and Staff are overrideable, but via a user switch, not temporary access. This satisfies both your preference (nothing is a dead end) and the PM's security concern (cashier never gets elevated access).

Transactional override (refunds, coupons):
Cashier taps "Refund"
→ Modal: "Manager approval required"
→ Manager enters PIN on same modal
→ Action executes, cashier stays in their session
→ Single-use. Cashier continues normally.

Manager walks over, punches code, walks away. 5 seconds.
Screen-level override (settings, staff):
Cashier taps "Settings" in floating menu
→ Modal: "Manager access required"
→ Manager enters PIN on same modal
→ Session switches to that Manager
→ Manager is now the active POS user
→ Settings screen opens for the Manager
→ Manager finishes, taps "Lock" (or auto-lock on nav away)
→ Lock screen appears, next person enters their PIN

The cashier doesn't get settings access. The manager takes over, does the thing, and the device returns to the lock screen. No "temporary elevation" ambiguity.
Exit POS (app boundary):
Anyone taps "Exit POS"
→ Modal: "Only the account owner can exit POS"
→ Only the app account holder's PIN works
→ App exits POS, returns to WooCommerce tabs

Three Override Tiers - Summary

Tier Actions What happens Who can authorize
Transactional Refunds, create coupons Manager PIN in modal, action executes, cashier continues Any Manager
Session Switch Settings, Staff mgmt Manager PIN switches active user, manager uses the screen, then locks Any Manager
App Boundary Exit POS Account holder's PIN required, exits POS to full app App account holder only
This model means nothing is a dead end. A cashier can always initiate any action. The system decides whether it proceeds immediately (allowed), needs a manager PIN (transactional), needs a session switch (administrative), or needs the account holder (exit POS). No confusion about what's possible - just different authorization levels.
