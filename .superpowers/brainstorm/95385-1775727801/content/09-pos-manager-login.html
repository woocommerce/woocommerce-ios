Should POS Manager log into the app?

This determines who can set up POS devices and who needs PINs configured in wp-admin

The Real-World Question

Alice (administrator) owns the coffee shop. She has 2 iPads.
Bob (pos_manager WP role) is the store manager. He opens and closes the shop daily.
Carol, Dave (pos_cashier WP role) are part-time cashiers.

Alice sets up iPad #1. She logs in, enables POS, creates PINs for everyone.

Now Alice wants to set up iPad #2. She's not at the store.
Can Bob set it up? That depends on whether pos_manager can log into the app.
A

POS Manager = PIN only (no app login)

Simpler model. Only admin/shop_manager can log into the app and set up POS devices. pos_manager and pos_cashier exist only via PIN. Alice must set up every device herself (or share her WP credentials, which is bad practice).

Pros

  • Clean separation: app login = full access, PIN = POS only
  • No ambiguity about what pos_manager sees
  • Fewer eligible roles to manage

Cons

  • Owner must physically set up every device
  • Manager can't onboard new iPads
  • Doesn't scale for multi-location
B

POS Manager = can log into app (POS-only mode)

More flexible. pos_manager can log into the app, but the app automatically enters POS mode. They never see the full WooCommerce tabs (orders, products, analytics). The app is essentially a POS-only experience for them.

Pros

  • Manager can set up new devices independently
  • Scales to multi-location
  • Manager is the "device owner" on their iPad

Cons

  • Need a "POS-only" app mode (skip main tabs)
  • pos_manager needs PIN setup in wp-admin
  • More complexity in the eligibility/routing logic
C

V1: PIN only. V2: App login with POS-only mode

Ship simple, evolve. For V1, pos_manager is PIN-only (same as cashier but with more POS permissions). In V2, add the ability for pos_manager to log in and get a POS-only app experience. This is the phased approach.

Pros

  • V1 stays simple - only 2 app-eligible roles
  • Buys time to design POS-only app mode properly
  • Can test the concept with merchants first

Cons

  • Multi-device setup requires owner for V1
  • Two-phase adds some migration complexity

If B or C (eventually): What changes?

App Routing

  • After login, check role
  • admin/shop_manager → normal app (all tabs)
  • pos_manager → straight to POS (no tabs)
  • pos_cashier → error screen (PIN only)

PIN Management

  • Admin sets PINs for everyone in wp-admin
  • pos_manager sets own PIN during first POS launch
  • pos_manager can set PINs for cashiers in POS Settings
  • Remote implementation handles PIN storage on server
Defense in depth note: Your backend-fallback pattern works perfectly here. Even if a pos_manager somehow accesses a WooCommerce REST endpoint they shouldn't, the backend checks their capabilities and rejects it. The app catches the 403, shows a manager override prompt if the action is overrideable, or a clean error if not.
